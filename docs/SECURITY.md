# 권한 및 운영 보안

- **이메일 확인**: 호스팅 설정에서 이메일 확인을 사용한다. Auth가 실제 OTP를 검증한 계정의 현재 확인 이메일만 학교 인증에 사용한다. 프로필 학교 값이나 사용자가 입력한 별도 문자열은 인증 입력이 아니다. 외부 OAuth와 대체 인증은 미지원이다.
- **승인된 학교 도메인만**: 실제 학생 계정만을 구분하는 도메인인지 대학 IT 안내와 운영자 확인을 거쳐 등록한다. 직원·졸업생까지 같은 도메인이면 도메인만으로 재학생을 판정할 수 없으므로 등록하지 말고 별도 검증을 설계한다. 비활성화, 이메일 변경, 서버 측 인증 취소 시 생성·합류를 다시 막는다. 기존 멤버십 자체는 자동 삭제하지 않는다.
- **최소 권한**: 7개 공개 스키마 테이블 모두 RLS를 적용한다. 공개 프로젝트는 공개용 컬럼만, 비공개 프로젝트는 멤버만 조회한다. 프로필은 기본 비공개, 본인이 공개를 선택한 경우만 방문자가 조회 가능하다. 프로젝트의 팀원 목록에는 닉네임과 역할만 표시된다.
- **초대**: 32바이트 난수, SHA-256 해시만 저장, 7일 만료, 1인 사용, 팀장 취소 가능. 링크를 가진 인증 학생은 수락할 수 있는 지참인 링크이므로 대상에게만 전달한다. 프래그먼트로 전달하고 수락 후 URL에서 제거한다. 서버 측 텔레메트리에 토큰이나 OTP 원문을 남기지 않는다.
- **API 쓰기**: 클라이언트는 자기 프로필의 허용 필드만 직접 수정한다. 특권 RPC는 `security definer` 및 빈 검색 경로를 사용하고 `authenticated` 실행만 허용한다. 초대와 프로젝트 생성에 DB 일일 한도를 두고 Auth에는 이메일 발송 빈도 제한을 설정한다.
- **공개 전 추가 작업**: 프로덕션 SMTP·발신 도메인과 인증 발송 한도 설정, 남용 신고와 운영 대응, 계정 삭제 요청/보존 규칙, 운영 관측성 검토. 앱 관리 화면은 미구현이며 학교 도메인은 권한 있는 DB 운영자가 등록한다.
- **후속 단계**: 익명 피드백·크레딧 원장은 스키마도 구현하지 않았다. 피드백은 제출 원문 비공개·최소 응답 수 집계, 크레딧은 비금전 원장·원자 거래·멱등 키를 별도 권한 테스트와 함께 설계한다.
