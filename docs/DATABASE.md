# 데이터베이스

초기 마이그레이션: `supabase/migrations/20261123000100_phase_one.sql`. DB 타입: `src/lib/supabase/database.types.ts` (로컬 스키마에서 생성).

| 테이블                     | 역할과 주요 제약                                                               |
| -------------------------- | ------------------------------------------------------------------------------ |
| `universities`             | 학교 이름 고유, 활성 학교만 공개                                               |
| `university_email_domains` | 정규화된 도메인 고유, 학교를 참조하고 운영자만 관리                            |
| `university_verifications` | 계정당 한 건, 현재 확인된 Auth 이메일과 활성 학교 도메인을 참조해 효력을 판단  |
| `profiles`                 | 계정과 1:1, 이용자가 선택한 학교는 인증 학교와 독립, 공개 범위 기본 비공개     |
| `projects`                 | 소유자·유형·상태·공개 범위, 시작일과 목표 종료일 제약; 소유자·공개 목록 인덱스 |
| `project_members`          | `(project_id,user_id)` 고유, 프로젝트별 팀장 한 명, 사용자별 목록 인덱스       |
| `project_invitations`      | 토큰 해시 고유, 상태·생성/만료/수락 시각, 프로젝트별 최근 목록 인덱스          |

프로젝트 생성 RPC는 프로젝트 행과 팀장 멤버십을 함께 커밋한다. 초대 수락 RPC는 초대 행을 잠그고 팀원 행 삽입과 초대 소진을 같은 트랜잭션에서 처리한다. 초대 원문은 DB에 저장하지 않는다.

계정 삭제 시 소유 프로젝트와 관련 행은 연쇄 삭제된다. 자기가 소유하지 않은 프로젝트의 멤버십과 자신이 보낸 초대도 삭제된다. 운영 공개 전 소유권 이전·보존 규칙을 정의해야 한다.

`supabase/seed.sql`은 초기 학교 목록을 반복 안전하게 추가한다. 초기 학교는 배포 마이그레이션에도 포함하지만 인증 이메일 도메인은 시드하지 않는다. pgTAP용 데이터는 롤백 트랜잭션, Playwright용 계정과 학교는 로컬 테스트에서만 생성한다.
